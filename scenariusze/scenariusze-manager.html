Subject: System obsługi warsztatu samochodowego (Car Service)
Use Case: Utwórz zlecenie naprawy na podstawie rezerwacji
Language: Polish
Preconditions:
  • Manager warsztatu musi być zalogowany do systemu
  • Musi istnieć rezerwacja wizyty na bieżący dzień
  • Klient musi dostarczyć pojazd do warsztatu
Postconditions:
  • Zlecenie naprawy zostało utworzone ze statusem „przyjęte” i powiązane z klientem oraz pojazdem
  • Zlecenie zostało przydzielone mechanikowi
  • Rezerwacja została oznaczona jako zrealizowana
  • Zlecenie jest widoczne dla klienta w systemie
Actors:
  • Manager warsztatu
Main flow:
  1. Manager wybiera opcję Rezerwacje
  2. System wyświetla listę rezerwacji na bieżący dzień
  3. Manager wybiera rezerwację klienta, który dostarczył pojazd
  4. System wyświetla szczegóły rezerwacji (klient, pojazd, termin, opis usterki)
  5. Manager wybiera opcję Utwórz zlecenie
  6. System wyświetla formularz zlecenia naprawy wypełniony danymi z rezerwacji
  7. Manager uzupełnia formularz (aktualny przebieg, opis usterki po oględzinach pojazdu)
  8. Manager przydziela zlecenie mechanikowi (przypadek użycia Przydziel zlecenie mechanikowi)
  9. Manager zapisuje zlecenie
  10. System dokonuje walidacji formularza
  11. System tworzy zlecenie naprawy ze statusem „przyjęte” i datą przyjęcia
  12. System oznacza rezerwację jako zrealizowaną
  13. System wyświetla potwierdzenie utworzenia zlecenia
Alternate flow:
  • 3 Na liście nie ma rezerwacji klienta, który dostarczył pojazd System nie pozwala utworzyć zlecenia bez rezerwacji END FLOW
  • 5 Rezerwacja nie została jeszcze potwierdzona Manager potwierdza rezerwację, a system zmienia jej status na „potwierdzona” GOTO 6
  • 9 Manager wybiera opcję Anuluj zamiast zapisania zlecenia System nie tworzy zlecenia END FLOW
  • 10 Nie wszystkie wymagane pola zostały wypełnione System zaznacza brakujące pola GOTO 6
  • 10 Podany przebieg jest mniejszy niż ostatnio zapisany przebieg pojazdu System wyświetla komunikat o błędnym przebiegu GOTO 6
  • 10 Zlecenie nie zostało przydzielone żadnemu mechanikowi System wyświetla komunikat o konieczności przydzielenia mechanika GOTO 8

Use Case: Przydziel zlecenie mechanikowi
Language: Polish
Preconditions:
  • Manager warsztatu musi być zalogowany do systemu
  • Musi istnieć zlecenie naprawy, które nie zostało zakończone ani rozliczone
  • W warsztacie musi być zatrudniony co najmniej jeden mechanik
Postconditions:
  • Zlecenie naprawy zostało przypisane do wybranego mechanika
  • Zlecenie jest widoczne na liście zleceń mechanika
  • Mechanik został poinformowany o nowym zleceniu
Actors:
  • Manager warsztatu
Main flow:
  1. Manager wybiera opcję Przydziel mechanika w szczegółach zlecenia
  2. System wyświetla listę mechaników wraz z liczbą aktualnie realizowanych przez nich zleceń
  3. Manager wybiera mechanika z listy
  4. Manager zatwierdza przydział
  5. System sprawdza dostępność mechanika w dniu realizacji zlecenia
  6. System przypisuje zlecenie do mechanika
  7. System dodaje zlecenie do listy zleceń mechanika
  8. System informuje mechanika o nowym zleceniu
  9. System wyświetla potwierdzenie przydziału
Alternate flow:
  • 2 Żaden mechanik nie jest dostępny w dniu realizacji zlecenia System wyświetla komunikat o braku dostępnych mechaników END FLOW
  • 4 Manager wybiera opcję Anuluj System nie zmienia przydziału END FLOW
  • 5 Wybrany mechanik jest nieobecny w dniu realizacji zlecenia System wyświetla komunikat o nieobecności mechanika GOTO 2
  • 5 Wybrany mechanik ma już bardzo dużo zleceń w realizacji System wyświetla ostrzeżenie o dużym obciążeniu mechanika GOTO 2
  • 6 Zlecenie miało wcześniej przydzielonego innego mechanika System usuwa zlecenie z listy poprzedniego mechanika i informuje go o zmianie przydziału GOTO 7

Use Case: Zarządzaj cennikiem usług
Language: Polish
Preconditions:
  • Manager warsztatu musi być zalogowany do systemu
Postconditions:
  • Nowa usługa wraz ze stawką została dodana do cennika usług
  • Nowa stawka jest stosowana przy wyliczaniu kosztorysów i faktur
Actors:
  • Manager warsztatu
Main flow:
  1. Manager wybiera opcję Cennik usług
  2. System wyświetla listę usług serwisowych wraz ze stawkami
  3. Manager wybiera opcję Dodaj usługę
  4. System wyświetla formularz usługi
  5. Manager wypełnia formularz (nazwa usługi, opis, stawka za roboczogodzinę lub cena stała, szacowany czas wykonania)
  6. Manager zapisuje formularz
  7. System dokonuje walidacji formularza
  8. System zapisuje usługę w cenniku wraz z datą obowiązywania stawki
  9. System wyświetla zaktualizowany cennik usług
Alternate flow:
  • 3 Manager wybiera opcję Edytuj przy istniejącej usłudze System wyświetla formularz wypełniony aktualnymi danymi usługi GOTO 5
  • 3 Manager wybiera opcję Usuń przy istniejącej usłudze System oznacza usługę jako nieaktywną, przez co nie jest ona dostępna w nowych naprawach i kosztorysach GOTO 2
  • 6 Manager wybiera opcję Anuluj zamiast zapisania formularza System nie zapisuje zmian GOTO 2
  • 7 Nie wszystkie wymagane pola zostały wypełnione System zaznacza brakujące pola GOTO 4
  • 7 Podana stawka jest niepoprawna (zerowa lub ujemna) System wyświetla komunikat o błędnej stawce GOTO 4
  • 7 Usługa o podanej nazwie już istnieje w cenniku System wyświetla komunikat o istniejącej usłudze GOTO 4
  • 8 Edytowana usługa jest użyta w otwartych zleceniach lub kosztorysach System stosuje nową stawkę tylko w nowych naprawach i kosztorysach GOTO 9

Use Case: Wystaw fakturę
Language: Polish
Preconditions:
  • Manager warsztatu musi być zalogowany do systemu
  • Zlecenie naprawy musi mieć status „zakończone”
  • Zlecenie musi zawierać co najmniej jedną wykonaną naprawę
Postconditions:
  • Faktura została wystawiona i powiązana ze zleceniem naprawy
  • Status zlecenia został zmieniony na „rozliczone”
  • Faktura jest dostępna dla klienta w systemie
Actors:
  • Manager warsztatu
Main flow:
  1. Manager wybiera opcję Zlecenia do rozliczenia
  2. System wyświetla listę zleceń naprawy o statusie „zakończone”
  3. Manager wybiera zlecenie z listy
  4. System wyświetla podsumowanie kosztów zlecenia (robocizna według cennika, użyte części, zaakceptowane kosztorysy)
  5. Manager wybiera opcję Wystaw fakturę
  6. System wyświetla formularz faktury wypełniony danymi klienta i pozycjami zlecenia
  7. Manager uzupełnia dane faktury (forma płatności, opcjonalnie NIP firmy klienta)
  8. Manager zatwierdza fakturę
  9. System dokonuje walidacji danych faktury
  10. System generuje fakturę z kolejnym numerem
  11. System zmienia status zlecenia na „rozliczone” (przypadek użycia Zmień status zlecenia naprawy)
  12. System udostępnia fakturę klientowi
  13. System wyświetla fakturę do wydruku
Alternate flow:
  • 2 Brak zleceń o statusie „zakończone” System wyświetla komunikat o braku zleceń do rozliczenia END FLOW
  • 5 Pozycja zlecenia nie ma ceny (usługa bez stawki w cenniku lub część bez ceny) System wskazuje pozycje bez ceny i nie pozwala wystawić faktury GOTO 2
  • 8 Manager wybiera opcję Anuluj zamiast zatwierdzenia faktury System nie wystawia faktury GOTO 4
  • 9 Nie wszystkie wymagane pola zostały wypełnione System zaznacza brakujące pola GOTO 6
  • 9 Podany numer NIP jest niepoprawny System wyświetla komunikat o błędnym numerze NIP GOTO 6
