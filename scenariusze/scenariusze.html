Use Case: Dodaj pojazd
Language: Polish
Preconditions:
  • Klient musi być zalogowany do systemu
Postconditions:
  • Pojazd został zapisany w systemie i przypisany do konta klienta
  • Pojazd jest dostępny do wyboru podczas rezerwacji wizyty
Actors:
  • Klient
Main flow:
  1. Klient wybiera opcję Moje pojazdy
  2. System wyświetla listę pojazdów przypisanych do konta klienta
  3. Klient wybiera opcję Dodaj pojazd
  4. System wyświetla formularz danych pojazdu
  5. Klient wypełnia formularz (marka, model, rok produkcji, numer VIN, numer rejestracyjny, przebieg)
  6. Klient wysyła formularz
  7. System dokonuje walidacji formularza
  8. System sprawdza, czy pojazd o podanym numerze VIN nie jest już zarejestrowany w systemie
  9. System zapisuje pojazd i przypisuje go do konta klienta
  10. System wyświetla zaktualizowaną listę pojazdów klienta
Alternate flow:
  • 6 Klient wybiera opcję Anuluj zamiast wysłania formularza System nie zapisuje pojazdu GOTO 2
  • 7 Nie wszystkie wymagane pola zostały wypełnione System zaznacza brakujące pola GOTO 4
  • 7 Numer VIN jest niepoprawny (nie składa się z 17 znaków) System wyświetla komunikat o błędnym numerze VIN GOTO 4
  • 7 Rok produkcji lub przebieg jest niepoprawny (np. rok z przyszłości, ujemny przebieg) System wyświetla komunikat o błędnych danych GOTO 4
  • 8 Pojazd o podanym numerze VIN jest już przypisany do konta klienta System informuje, że pojazd został już dodany GOTO 2
  • 8 Pojazd o podanym numerze VIN jest przypisany do innego klienta System informuje o konieczności kontaktu z warsztatem END FLOW

Use Case: Zarezerwuj wizytę
Language: Polish
Preconditions:
  • Klient musi być zalogowany do systemu
  • W kalendarzu warsztatu musi być co najmniej jeden wolny termin
Postconditions:
  • Rezerwacja wizyty została zapisana ze statusem „oczekuje na potwierdzenie”
  • Wybrany termin został zablokowany w kalendarzu warsztatu
  • Rezerwacja jest widoczna dla managera warsztatu do potwierdzenia
Actors:
  • Klient
Main flow:
  1. Klient wybiera opcję Zarezerwuj wizytę
  2. System wyświetla listę pojazdów klienta
  3. Klient wybiera pojazd z listy
  4. System wyświetla kalendarz z wolnymi terminami
  5. Klient wybiera termin wizyty
  6. System wyświetla formularz opisu usterki
  7. Klient wpisuje opis usterki
  8. Klient wysyła formularz
  9. System dokonuje walidacji formularza
  10. System sprawdza, czy wybrany termin jest nadal wolny
  11. System zapisuje rezerwację ze statusem „oczekuje na potwierdzenie” i blokuje termin
  12. System przekazuje rezerwację managerowi warsztatu do potwierdzenia
  13. System wyświetla potwierdzenie złożenia rezerwacji
Alternate flow:
  • 2 Klient nie ma przypisanego żadnego pojazdu Klient dodaje pojazd (przypadek użycia Dodaj pojazd) GOTO 2
  • 3 Klient wybiera opcję Dodaj nowy pojazd Klient dodaje pojazd (przypadek użycia Dodaj pojazd) GOTO 2
  • 3 Wybrany pojazd ma już aktywną rezerwację lub otwarte zlecenie naprawy System informuje o istniejącej rezerwacji lub zleceniu GOTO 2
  • 4 Brak wolnych terminów w wyświetlanym tygodniu Klient przechodzi do kolejnego tygodnia GOTO 4
  • 8 Klient wybiera opcję Anuluj zamiast wysłania formularza System nie tworzy rezerwacji END FLOW
  • 9 Opis usterki nie został wpisany System zaznacza brakujące pole GOTO 6
  • 10 Wybrany termin został w międzyczasie zajęty przez innego klienta System informuje, że termin jest już niedostępny GOTO 4

Use Case: Śledź status zlecenia naprawy
Language: Polish
Preconditions:
  • Klient musi być zalogowany do systemu
Postconditions:
  • Klient zapoznał się z aktualnym statusem i historią zlecenia naprawy
  • Stan zlecenia w systemie nie uległ zmianie
Actors:
  • Klient
Main flow:
  1. Klient wybiera opcję Moje zlecenia
  2. System wyświetla listę zleceń naprawy klienta wraz z aktualnymi statusami
  3. Klient wybiera zlecenie z listy
  4. System wyświetla szczegóły zlecenia (pojazd, status, przydzielony mechanik, wykonane naprawy, bieżący koszt)
  5. Klient wybiera opcję Historia statusów
  6. System wyświetla historię zmian statusu zlecenia wraz z datami i komentarzami mechanika
Alternate flow:
  • 2 Klient nie ma żadnych zleceń naprawy System wyświetla komunikat o braku zleceń END FLOW
  • 4 Zlecenie ma status „oczekuje na akceptację kosztorysu” Klient przechodzi do kosztorysu (przypadek użycia Zaakceptuj kosztorys dodatkowych prac) GOTO 4
  • 4 Zlecenie ma status „zakończone” System wyświetla informację, że pojazd jest gotowy do odbioru GOTO 5
  • 5 Klient wybiera opcję Wróć do listy GOTO 2

Use Case: Zaakceptuj kosztorys dodatkowych prac
Language: Polish
Preconditions:
  • Klient musi być zalogowany do systemu
  • Zlecenie naprawy klienta musi mieć status „oczekuje na akceptację kosztorysu”
  • Mechanik musi utworzyć kosztorys dodatkowych prac
Postconditions:
  • Decyzja klienta została zapisana w zleceniu naprawy
  • Prace z kosztorysu zostały dodane do zlecenia, a koszt zlecenia został przeliczony
  • Status zlecenia został zmieniony na „w trakcie realizacji”
  • Mechanik został poinformowany o decyzji klienta
Actors:
  • Klient
Main flow:
  1. Klient wybiera opcję Zobacz kosztorys w szczegółach zlecenia
  2. System wyświetla kosztorys (opis usterki, usługi, części, koszt robocizny, koszt części, koszt łączny)
  3. Klient wybiera opcję Akceptuj
  4. System prosi o potwierdzenie decyzji
  5. Klient potwierdza decyzję
  6. System sprawdza, czy kosztorys nie został w międzyczasie zmieniony
  7. System zapisuje akceptację kosztorysu
  8. System dodaje prace z kosztorysu do zlecenia i przelicza koszt zlecenia
  9. System zmienia status zlecenia na „w trakcie realizacji”
  10. System informuje mechanika o akceptacji kosztorysu
  11. System wyświetla potwierdzenie akceptacji
Alternate flow:
  • 3 Klient wybiera opcję Odrzuć System zapisuje odrzucenie kosztorysu, zmienia status zlecenia na „w trakcie realizacji” i informuje mechanika, że dodatkowe prace nie zostaną wykonane END FLOW
  • 3 Klient wybiera opcję Wróć bez podejmowania decyzji Status zlecenia nie ulega zmianie END FLOW
  • 5 Klient rezygnuje z potwierdzenia decyzji GOTO 2
  • 6 Kosztorys został w międzyczasie zmieniony przez mechanika System wyświetla informację o zmianie kosztorysu GOTO 2

Use Case: Zamów części u magazyniera
Language: Polish
Preconditions:
  • Mechanik musi być zalogowany do systemu
  • Mechanikowi musi być przydzielone zlecenie naprawy o statusie „w trakcie realizacji”
Postconditions:
  • Zamówienie części zostało utworzone i przypisane do zlecenia naprawy
  • Zamówienie jest widoczne dla magazyniera na liście zamówień do realizacji
Actors:
  • Mechanik
  • Manager warsztatu
Main flow:
  1. Mechanik wybiera opcję Moje zlecenia
  2. System wyświetla listę zleceń naprawy przydzielonych mechanikowi
  3. Mechanik wybiera zlecenie z listy
  4. System wyświetla szczegóły zlecenia
  5. Mechanik wybiera opcję Zamów części
  6. System wyświetla katalog części z wyszukiwarką
  7. Mechanik wyszukuje potrzebne części, wybiera je i podaje ilość
  8. Mechanik wysyła zamówienie
  9. System dokonuje walidacji zamówienia
  10. System tworzy zamówienie części i przypisuje je do zlecenia naprawy
  11. System przekazuje zamówienie magazynierowi
  12. System wyświetla potwierdzenie złożenia zamówienia
Alternate flow:
  • 2 Mechanik nie ma przydzielonych żadnych zleceń System wyświetla komunikat o braku zleceń END FLOW
  • 5 Zlecenie ma status „zakończone” lub „rozliczone” System informuje, że do zlecenia nie można zamawiać części GOTO 2
  • 7 Szukanej części nie ma w katalogu System wyświetla komunikat o braku wyników GOTO 6
  • 8 Mechanik wybiera opcję Anuluj zamiast wysłania zamówienia System nie tworzy zamówienia GOTO 4
  • 9 Nie wybrano żadnej części lub podana ilość jest niepoprawna System wyświetla komunikat o błędnych danych GOTO 6
  • 9 Ta sama część została już zamówiona do tego zlecenia i nie została jeszcze wydana System wyświetla informację o istniejącym zamówieniu GOTO 6

Use Case: Wprowadź wykonaną naprawę
Language: Polish
Preconditions:
  • Mechanik musi być zalogowany do systemu
  • Mechanikowi musi być przydzielone zlecenie naprawy o statusie „w trakcie realizacji”
  • Cennik usług musi zawierać co najmniej jedną usługę
Postconditions:
  • Naprawa (rodzaj usługi, opis czynności, czas pracy, użyte części) została zapisana w zleceniu naprawy
  • Koszt zlecenia został automatycznie przeliczony na podstawie cennika usług i użytych części
Actors:
  • Mechanik
  • Manager warsztatu
Main flow:
  1. Mechanik wybiera opcję Moje zlecenia
  2. System wyświetla listę zleceń naprawy przydzielonych mechanikowi
  3. Mechanik wybiera zlecenie z listy
  4. System wyświetla szczegóły zlecenia wraz z historią serwisową pojazdu
  5. Mechanik wybiera opcję Dodaj naprawę
  6. System wyświetla formularz naprawy z listą usług z cennika oraz listą części wydanych do zlecenia
  7. Mechanik wybiera rodzaj usługi, wpisuje opis czynności i czas pracy oraz zaznacza użyte części
  8. Mechanik zapisuje formularz
  9. System dokonuje walidacji formularza
  10. System zapisuje naprawę w zleceniu
  11. System przelicza koszt zlecenia na podstawie cennika usług i użytych części
  12. System wyświetla zaktualizowane zlecenie wraz z kosztem
Alternate flow:
  • 2 Mechanik nie ma przydzielonych żadnych zleceń System wyświetla komunikat o braku zleceń END FLOW
  • 5 Zlecenie ma status inny niż „w trakcie realizacji” System informuje, że do zlecenia nie można dodać naprawy GOTO 2
  • 7 Mechanik wykrył dodatkową usterkę Mechanik zgłasza usterkę (przypadek użycia Zgłoś dodatkową usterkę) GOTO 6
  • 7 Potrzebna część nie została jeszcze wydana do zlecenia System wyświetla informację o konieczności zamówienia części u magazyniera GOTO 4
  • 8 Mechanik wybiera opcję Anuluj zamiast zapisania formularza System nie zapisuje naprawy GOTO 4
  • 9 Nie wszystkie wymagane pola zostały wypełnione System zaznacza brakujące pola GOTO 6
  • 9 Czas pracy jest niepoprawny (np. zerowy lub ujemny) System wyświetla komunikat o błędnych danych GOTO 6

Use Case: Zgłoś dodatkową usterkę
Language: Polish
Preconditions:
  • Mechanik musi być zalogowany do systemu
  • Mechanik musi wprowadzać naprawę w zleceniu o statusie „w trakcie realizacji” (przypadek użycia Wprowadź wykonaną naprawę)
Postconditions:
  • Dodatkowa usterka została zapisana w zleceniu naprawy
  • Kosztorys dodatkowych prac został utworzony i udostępniony klientowi do akceptacji
  • Status zlecenia został zmieniony na „oczekuje na akceptację kosztorysu”
Actors:
  • Mechanik
  • Manager warsztatu
Main flow:
  1. Mechanik wybiera opcję Zgłoś dodatkową usterkę w formularzu naprawy
  2. System wyświetla formularz zgłoszenia usterki
  3. Mechanik wpisuje opis usterki oraz wybiera potrzebne usługi z cennika i części
  4. Mechanik wysyła formularz
  5. System dokonuje walidacji formularza
  6. System wylicza kosztorys (koszt robocizny i części) na podstawie cennika usług
  7. System wyświetla podgląd kosztorysu
  8. Mechanik zatwierdza kosztorys
  9. System zapisuje usterkę i kosztorys w zleceniu naprawy
  10. System zmienia status zlecenia na „oczekuje na akceptację kosztorysu”
  11. System udostępnia kosztorys klientowi do akceptacji
  12. System wyświetla potwierdzenie zgłoszenia usterki
Alternate flow:
  • 4 Mechanik wybiera opcję Anuluj zamiast wysłania formularza System nie zapisuje zgłoszenia i wraca do formularza naprawy END FLOW
  • 5 Opis usterki nie został wpisany lub nie wybrano żadnej usługi System zaznacza brakujące pola GOTO 2
  • 6 Wybrana usługa nie ma aktualnej stawki w cenniku System wyświetla komunikat o braku stawki GOTO 2
  • 8 Mechanik wybiera opcję Popraw GOTO 2

Use Case: Zmień status zlecenia naprawy
Language: Polish
Preconditions:
  • Mechanik musi być zalogowany do systemu
  • Mechanikowi musi być przydzielone zlecenie naprawy
Postconditions:
  • Status zlecenia naprawy został zmieniony i zapisany wraz z datą zmiany
  • Zmiana statusu jest widoczna dla klienta i managera warsztatu
Actors:
  • Mechanik
  • Manager warsztatu
Main flow:
  1. Mechanik wybiera opcję Moje zlecenia
  2. System wyświetla listę zleceń naprawy przydzielonych mechanikowi
  3. Mechanik wybiera zlecenie z listy
  4. System wyświetla szczegóły zlecenia wraz z aktualnym statusem
  5. Mechanik wybiera opcję Zmień status
  6. System wyświetla listę statusów dozwolonych dla bieżącego etapu zlecenia
  7. Mechanik wybiera nowy status i opcjonalnie dodaje komentarz
  8. Mechanik zatwierdza zmianę
  9. System sprawdza, czy zmiana statusu jest dozwolona
  10. System zapisuje nowy status wraz z datą zmiany
  11. System wyświetla potwierdzenie zmiany statusu
Alternate flow:
  • 2 Mechanik nie ma przydzielonych żadnych zleceń System wyświetla komunikat o braku zleceń END FLOW
  • 5 Zlecenie ma status „rozliczone” System informuje, że zmiana statusu nie jest możliwa GOTO 2
  • 8 Mechanik wybiera opcję Anuluj Status zlecenia nie ulega zmianie GOTO 4
  • 9 Wybrano status „zakończone”, ale w zleceniu nie zapisano żadnej naprawy System wyświetla komunikat o braku wykonanych napraw GOTO 6
  • 9 Wybrano status „zakończone”, ale kosztorys dodatkowych prac oczekuje na decyzję klienta System wyświetla komunikat o oczekującym kosztorysie GOTO 6

Use Case: Sprawdź dostępność części
Language: Polish
Preconditions:
  • Magazynier musi być zalogowany do systemu
  • Katalog części musi zawierać co najmniej jedną część
Postconditions:
  • Magazynier zna aktualny stan magazynowy wybranej części
  • Stan magazynowy w systemie nie uległ zmianie
Actors:
  • Magazynier
Main flow:
  1. Magazynier wybiera opcję Sprawdź dostępność części
  2. System wyświetla wyszukiwarkę części
  3. Magazynier wpisuje nazwę lub numer katalogowy części
  4. System wyświetla listę części pasujących do zapytania
  5. Magazynier wybiera część z listy
  6. System wyświetla szczegóły części (nazwa, numer katalogowy, producent, cena)
  7. System wyświetla aktualny stan magazynowy części oraz ilość zarezerwowaną dla zleceń naprawy
  8. System oznacza część jako dostępną
Alternate flow:
  • 4 Brak części pasujących do zapytania System wyświetla komunikat o braku wyników GOTO 2
  • 5 Magazynier wybiera opcję Zmień zapytanie GOTO 3
  • 8 Stan magazynowy części wynosi zero System oznacza część jako niedostępną; magazynier może zamówić część (przypadek użycia Zamów części u dostawcy) END FLOW
  • 8 Dostępna ilość części jest mniejsza niż ilość zamówiona przez mechanika System wyświetla brakującą ilość; magazynier może zamówić część (przypadek użycia Zamów części u dostawcy) END FLOW

Use Case: Wydaj części mechanikowi
Language: Polish
Preconditions:
  • Magazynier musi być zalogowany do systemu
  • Musi istnieć co najmniej jedno niezrealizowane zamówienie części złożone przez mechanika
Postconditions:
  • Części zostały wydane mechanikowi i przypisane do zlecenia naprawy
  • Stan magazynowy części został pomniejszony o wydaną ilość
  • Zamówienie części zostało oznaczone jako zrealizowane
  • Mechanik został poinformowany o wydaniu części
Actors:
  • Magazynier
Main flow:
  1. Magazynier wybiera opcję Zamówienia części
  2. System wyświetla listę niezrealizowanych zamówień części od mechaników
  3. Magazynier wybiera zamówienie z listy
  4. System wyświetla szczegóły zamówienia (zlecenie naprawy, mechanik, części, ilości)
  5. Magazynier wybiera opcję Wydaj części
  6. System sprawdza dostępność zamówionych części (przypadek użycia Sprawdź dostępność części)
  7. System wyświetla podsumowanie wydania
  8. Magazynier potwierdza wydanie części
  9. System przypisuje wydane części do zlecenia naprawy
  10. System pomniejsza stan magazynowy części
  11. System oznacza zamówienie części jako zrealizowane
  12. System informuje mechanika o wydaniu części
  13. System wyświetla potwierdzenie wydania
Alternate flow:
  • 2 Brak niezrealizowanych zamówień części System wyświetla komunikat o braku zamówień END FLOW
  • 6 Zamówiona część jest niedostępna w magazynie System oznacza zamówienie jako oczekujące i zmienia status zlecenia na „oczekuje na części”; magazynier może zamówić część (przypadek użycia Zamów części u dostawcy) END FLOW
  • 6 Dostępna ilość części jest mniejsza niż zamówiona System proponuje częściowe wydanie, a pozostała ilość zostaje w zamówieniu jako oczekująca GOTO 7
  • 8 Magazynier wybiera opcję Anuluj System nie wydaje części GOTO 4
  • 9 Zlecenie naprawy zostało w międzyczasie zakończone lub rozliczone System anuluje zamówienie części i nie zmienia stanu magazynowego END FLOW

Use Case: Zamów części u dostawcy
Language: Polish
Preconditions:
  • Magazynier musi być zalogowany do systemu
  • Część musi być niedostępna lub jej ilość w magazynie musi być niewystarczająca (przypadek użycia Sprawdź dostępność części)
  • W systemie musi być zarejestrowany co najmniej jeden dostawca
Postconditions:
  • Zamówienie u dostawcy zostało zapisane ze statusem „wysłane”
  • Zamówienie zostało wysłane do dostawcy
  • Brakujące części zostały oznaczone jako zamówione u dostawcy
Actors:
  • Magazynier
Main flow:
  1. Magazynier wybiera opcję Zamów u dostawcy w szczegółach brakującej części
  2. System wyświetla formularz zamówienia z listą dostawców oferujących część
  3. Magazynier wybiera dostawcę i podaje ilość części
  4. Magazynier wysyła formularz
  5. System dokonuje walidacji formularza
  6. System wyświetla podsumowanie zamówienia (cena, przewidywany termin dostawy)
  7. Magazynier potwierdza zamówienie
  8. System zapisuje zamówienie u dostawcy ze statusem „wysłane”
  9. System wysyła zamówienie do dostawcy
  10. System oznacza brakujące części jako zamówione u dostawcy
  11. System wyświetla potwierdzenie złożenia zamówienia
Alternate flow:
  • 2 Żaden dostawca nie oferuje wybranej części System wyświetla komunikat o braku dostawcy END FLOW
